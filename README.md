# CodeIgniter 4 POS System

## Project

This Point-of-Sale application was developed for **IT0049 - Web System Technologies** and extended for **Technical Formative Assessment 2: From Arrays to a Real Database**.

The original TFA1 routes, navigation, layout, and account pages are preserved. Customer and user records now follow this CodeIgniter MVC flow:

```text
MySQL database -> CodeIgniter Model -> Controller -> View -> HTML response
```

## Features

- Home and About pages from the original POS application
- Customer Accounts directory backed by the `customers` MySQL table
- User Accounts directory backed by the `users` MySQL table
- Database access through CodeIgniter Models and Query Builder methods
- Escaped database values and simple empty-table messages
- Reusable navigation, header, footer, and responsive styling
- Explicit routes with automatic routing disabled

## Requirements

- PHP 8.2 or newer, as required by `composer.json`
- Composer
- MySQL or MariaDB
- PHP extensions required by CodeIgniter 4, including `intl`, `mbstring`, and `mysqli`

## Installation and setup

1. Clone or download the repository, then enter its directory:

   ```bash
   cd pos-system
   ```

2. Install the PHP dependencies:

   ```bash
   composer install
   ```

3. Create the local environment file when one does not already exist:

   ```bash
   cp env .env
   ```

4. Configure the application and database connection in `.env`:

   ```ini
   CI_ENVIRONMENT = development
   app.baseURL = 'http://localhost:8080/'
   app.indexPage = ''

   database.default.hostname = 127.0.0.1
   database.default.database = pos_db
   database.default.username = root
   database.default.password =
   database.default.DBDriver = MySQLi
   database.default.DBPrefix =
   database.default.port = 3306
   ```

   Change the hostname, username, password, or port to match your local MySQL installation. `.env` is ignored by Git and must not be committed.

5. Start MySQL and import the included database setup file:

   ```bash
   mysql --host=127.0.0.1 --port=3306 -u root -p < database/pos_db.sql
   ```

   Enter your local MySQL password when prompted. You can alternatively import `database/pos_db.sql` through phpMyAdmin. The SQL file creates `pos_db`, recreates both required tables, and inserts the sample records.

6. Start the CodeIgniter development server:

   ```bash
   php spark serve
   ```

7. Open [http://localhost:8080/](http://localhost:8080/) in a browser.

## Database

The reproducible database setup file is located at:

```text
database/pos_db.sql
```

A verified export generated from the working `pos_db` database is also included at:

```text
database/pos_db_export.sql
```

Both files create `pos_db`, recreate the required tables, and insert the same sample records. Use `database/pos_db.sql` for the concise project setup or `database/pos_db_export.sql` when an export generated by MySQL is specifically required.

It uses the assessment's required tables and fields:

### `customers`

- `id`
- `full_name`
- `email`
- `phone`
- `created_at`

### `users`

- `id`
- `username`
- `full_name`
- `created_at`

The setup file contains five fictional customer records and five fictional user records. No password, role, status, address, or other fields are added to the supplied schema.

## CodeIgniter MVC structure

```text
app/
|-- Config/Routes.php
|-- Controllers/
|   |-- Customers.php
|   |-- Pages.php
|   `-- Users.php
|-- Models/
|   |-- CustomerModel.php
|   `-- UserModel.php
`-- Views/
    |-- customers/index.php
    |-- users/index.php
    |-- templates/
    |-- home.php
    `-- about.php
database/
|-- pos_db.sql
`-- pos_db_export.sql
public/
`-- assets/css/style.css
```

- `CustomerModel` accesses the `customers` table.
- `UserModel` accesses the `users` table.
- The account controllers call each model's `findAll()` method and pass the returned arrays to the existing views.
- The views use `foreach` to render the database records and do not execute database queries.

## Security and repository notes

- Do not commit `.env` or real database credentials.
- Composer dependencies in `vendor/` are excluded and can be restored with `composer install`.
- Runtime cache, log, session, debug, and upload contents under `writable/` are excluded.
- Commit the application source, `composer.json`, `composer.lock`, this README, and both SQL files under `database/`.

## Hosting requirements

A hosting environment must provide a compatible PHP version, the required PHP extensions, Composer-installed dependencies, a MySQL/MariaDB database, and a web server whose document root points to `public/`. Import `database/pos_db.sql` and configure production database credentials through environment settings on the host.
