# Tasks for Today Management System

This CodeIgniter 4 application was developed by **Isaiah Ezekiel P. Vicencio** for **IT0049 — Web System Technologies, Technical Summative Assessment 2**. It extends the original database-backed Tasks for Today system with authenticated task creation, editing, and soft archiving while keeping all task listings publicly readable.

## Features

- Public Today page showing only active tasks scheduled for the current date
- Public All Tasks page showing all active tasks ordered by `task_date` and `id`
- Public Profile page showing the single demonstration user
- Public About page identifying the project and developer
- Login and logout using a password hash stored in the database
- Session-based access control for task management routes
- Create and edit forms with server-side validation and preserved input
- Soft archive action using `is_archived`; task records are not physically deleted
- CSRF protection on all POST forms
- Database access through `TaskModel` and `UserModel`

## Requirements

- PHP 8.2 or newer
- Composer
- MySQL or MariaDB
- PHP extensions required by CodeIgniter 4, including `intl`, `mbstring`, and `mysqli`

## Installation and setup

1. Enter the standalone TSA2 project:

   ```bash
   cd tasks-for-today
   ```

2. Install dependencies:

   ```bash
   composer install
   ```

3. Create the local environment file:

   ```bash
   cp env .env
   ```

4. Configure `.env` for the local server and the dedicated database:

   ```ini
   CI_ENVIRONMENT = development
   app.baseURL = 'http://localhost:8080/'
   app.indexPage = ''
   app.appTimezone = 'Asia/Manila'

   database.default.hostname = 127.0.0.1
   database.default.database = tasks_today_db
   database.default.username = root
   database.default.password =
   database.default.DBDriver = MySQLi
   database.default.DBPrefix =
   database.default.port = 3306
   ```

   Change the database username, password, or port for the local MySQL installation. `.env` is ignored by Git and must not be committed.

5. Create a fresh database with the full TSA2 schema and demonstration data:

   ```bash
   mysql --host=127.0.0.1 --port=3306 -u root -p < database/tasks_today_db.sql
   ```

   The SQL script creates `tasks_today_db`, nine tasks spanning yesterday, today, and tomorrow, and exactly one user. The password begins as `NULL` so no shared password or password hash is published.

   To upgrade an existing TSA1 database without replacing its records, run the migration instead:

   ```bash
   php spark migrate
   ```

6. Privately choose the demo user's password in an interactive terminal:

   ```bash
   php spark auth:set-password isaiahvicencio
   ```

   Enter and confirm a password of at least 12 characters. The command stores only a value generated by PHP's `password_hash()`; it never prints or stores the plaintext password.

7. Start the development server:

   ```bash
   php spark serve
   ```

8. Open [http://localhost:8080/](http://localhost:8080/). Sign in with username `isaiahvicencio` and the private password chosen in step 6.

## Routes

### Public routes

| Method | URL | Controller method | Purpose |
| --- | --- | --- | --- |
| GET | `/` | `Tasks::today` | Active tasks scheduled for today |
| GET | `/tasks` | `Tasks::index` | Every active task ordered by date |
| GET | `/profile` | `Users::index` | The single database user (never exposes the password hash) |
| GET | `/about` | `Pages::about` | Project and developer information |
| GET | `/login` | `Auth::login` | Login form |
| POST | `/login` | `Auth::authenticate` | Verify credentials and begin a session |

### Authenticated routes

| Method | URL | Controller method | Purpose |
| --- | --- | --- | --- |
| POST | `/logout` | `Auth::logout` | End the authenticated session |
| GET | `/tasks/new` | `Tasks::new` | New-task form |
| POST | `/tasks` | `Tasks::create` | Validate and create a task |
| GET | `/tasks/{id}/edit` | `Tasks::edit` | Edit form for an active task |
| POST | `/tasks/{id}` | `Tasks::update` | Validate and update an active task |
| POST | `/tasks/{id}/archive` | `Tasks::archive` | Soft archive an active task |

Unauthorized management requests are redirected to `/login`. After a successful login, safe requested form pages are restored; otherwise the user is sent to `/tasks`.

## Database and migrations

The reproducible fresh-install SQL is [`database/tasks_today_db.sql`](database/tasks_today_db.sql). The migration [`app/Database/Migrations/2026-10-09-175500_AddTsa2Fields.php`](app/Database/Migrations/2026-10-09-175500_AddTsa2Fields.php) upgrades the TSA1 tables by adding:

- `tasks.is_archived TINYINT(1) NOT NULL DEFAULT 0`
- `users.password VARCHAR(255) NULL`

The nullable initial password supports a safe setup flow: login remains unavailable until the project owner runs the private password command. Existing task and user records are preserved by the migration.

### Date handling

The application timezone is `Asia/Manila`, and the Today controller computes the date at request time. A fresh SQL import creates several records for `CURDATE()`. If an older TSA1 database contains only historical dates, preserve those records and create a new task dated today through the authenticated New Task form to demonstrate the Today filter; do not rewrite the historical sample dates.

## Security notes

- Passwords are checked with `password_verify()` and rehashed when needed.
- The session identifier is regenerated after successful login.
- The session stores only the user ID, username, and authenticated flag.
- Login errors do not disclose whether a username exists.
- Repeated failures have a short session-based throttle.
- Task POST forms use CodeIgniter's CSRF protection.
- The public Profile controller explicitly excludes the password field.
- `.env`, runtime files under `writable/`, and Composer dependencies under `vendor/` are not committed.

## Hosting requirements

A production host must provide a supported PHP version, required PHP extensions, Composer dependencies, and a MySQL or MariaDB database. Point the web server's document root to `public/`, set the production `app.baseURL`, use production mode, import the TSA2 schema (or run migrations against the deployed database), and set the demo password privately on the host. Keep `.env` and credentials outside version control, use HTTPS, and do not expose development error pages.

This assessment intentionally does not include registration, password recovery, roles, authorization levels, hard deletion, or other unrequested features.
